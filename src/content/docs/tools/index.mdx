A tool page on [tamperbox.dev](https://tamperbox.dev) has one job: take one input, show the verdict, and show the evidence behind it. The page keeps a short "How it works", the limits that change how you read a result, three questions people ask, and the standards it follows. Everything longer lives here.

Each tool's documentation has the same shape, so a finding on the page always has a place to point to:

| Section | What it holds | Where the page links to it |
| --- | --- | --- |
| Method | Every rule the tool applies, in the order it applies them, with the exact wording of each finding | "Read the method" on the What does it mean and Tool limitations cards |
| Finding reference | One row per finding: severity, what it means for whoever receives the output, the fix | The finding itself |
| Guide | Step by step, for each situation the tool can put you in, including how to verify the fix | "Step by step on docs" on the How to fix it card |
| Worked example | The live default or controlled sample the page opens on, read end to end, and what each Break it case shows | "Worked examples on docs" |
| For agents | How to run the same check through the MCP server and what the result does not prove | The For agents band on the page |

## Where processing happens

Every tool page says, next to its verdict, where your input goes. The rule is the same across tools:

- **Pasted input stays in your browser.** A certificate chain, a DNS record, a message header: the page reads it locally and sends nothing.
- **A host name or domain means a named server-side check.** The server makes the required connection, DNS queries or published-file fetches, returns what it saw, and keeps nothing. The page names the port and the records or files it checks before it runs them.

Nothing you enter is stored, put in a URL, or shown to advertisers.

## Break it, Heal it, History

Every tool page has three controls that belong together:

- **Break it** loads a deliberate edge case built from your own input where that is possible, so you see what the finding looks like before it happens to you.
- **Heal it** offers the repairs the tool found, each saying what it will change. After a break with no repair, it offers to restore the input you had before.
- **History**, under the result, logs every change with what it replaced. Revert undoes the newest change; Reset input returns to what you entered.
