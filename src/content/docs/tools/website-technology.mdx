The tool page is [tamperbox.dev/website-technology](https://tamperbox.dev/website-technology). It opens on `www.harbor-supply.example`, a sample shop on the reserved `.example` zone whose page and headers are a fixture. This page is the long version: what the detector reads, every rule it applies, what each finding means for the people who run the site, and how to fix and confirm each one.

<div class="tb-callout"><strong>Where processing happens:</strong> a domain is sent to the Tamperbox server, which makes one HTTPS GET for the home page, follows up to three redirects, and returns the final response's status, headers and the first 256 KiB of its HTML. Detection then runs in your browser. Pasted HTML and headers never leave the browser. The sample is answered in the browser too. Nothing is stored.</div>

## What the tool answers

The detector answers, in order:

1. **What is the site built with?** A content system, a shop, a site builder, a static site generator or a JavaScript framework leads the verdict, with up to two companions and the CDN in front of it.
2. **What else does the page load?** Analytics, advertising, consent tools, payments, support widgets, monitoring, languages, web servers and hosting signals, grouped by what they do.
3. **What gave each one away?** Every detection lists the header line or the HTML text it matched, with the matched part marked.
4. **Does the site announce versions an attacker can use?** An exact version of a content system, a language, a web server or a server framework is a finding.
5. **Was the page the real page?** An error or challenge page, a non-HTML response, a truncated body and a failed TLS lookup are reported, so an empty or odd list is not mistaken for the site's stack.

It does not run the page's scripts, does not fetch stylesheets or script files, and does not test for vulnerabilities.

## Inputs

### A domain

`example.com`, or a full address pasted from the address bar. A pasted `https://www.example.com/about` becomes `www.example.com` in the box, and the hint says so; typing is never rewritten. The lookup runs when you stop typing (about 600 ms) or on Enter. The server only accepts public names on the default HTTPS port: names under `localhost`, `local`, `internal`, `intranet`, `lan`, `home`, `test`, `invalid`, `example`, `onion` and `arpa` are refused, every address the name resolves to must be public, and both A and AAAA lookups must succeed. The `.example` sample never reaches the server.

### Pasted HTML

Text that starts with `<` is read as HTML. Paste the page source from a browser (View source), or the rendered DOM from the developer tools when you want what scripts added.

### Pasted headers, or headers and HTML

Text that starts with an HTTP status line (`HTTP/1.1 200 OK`) or with `name: value` lines is read as response headers; anything after the first blank line is read as the HTML. This is the shape `curl -si https://example.com/` prints. A line that starts with a URL scheme (`https://`) is not mistaken for a header.

### JSON

Text that starts with `{` or `[` is reported as "Not a web page: this looks like JSON." An API response has no page to read.

### Files

Drop an `.html`, `.htm` or `.txt` file anywhere on the page, or use Add a file. Files up to 2 MiB are read in the browser.

## Reading the result

### Verdict and chips

The verdict leads with the first content system, shop, site builder, static site generator or JavaScript framework found, with its version when one was read, then up to two companions from those groups and the CDN: "WordPress 6.4.2 with WooCommerce, behind Cloudflare." When none of the lead groups matched it gives the count instead. Other verdicts: "Website not inspected" (a failed TLS lookup), "HTTP 503 page" (an error or challenge response), "Nothing recognised", and "Not a web page" for JSON. The chips count the technologies, the announced versions, an error status and the redirects; each is a button that scrolls to the section that explains it.

### Findings

Everything the detector flags, worst first; two or more passing checks fold into one line. The [finding reference](#finding-reference) lists them all.

### Take it further

Links that carry a value from this result into another tool: the final host after redirects to the [Security Headers Grader](https://tamperbox.dev/security-headers) and the [SSL Certificate Checker](https://tamperbox.dev/ssl-checker), the original address to the [Redirect Checker](https://tamperbox.dev/redirect-checker) when there were redirects, and the host to the [ads.txt checker](https://tamperbox.dev/ads-txt-checker) when Google AdSense was detected. The value travels through a one-use handoff, never in the URL. From the sample, every destination answers its own sample locally.

### History and Heal it

Every Break it case and Heal it repair is logged under the result with what it replaced. Revert undoes the newest change; Reset input returns to what you entered.

### Technologies

Grouped by category in a fixed order (content system first, hosting last). Each entry names the technology, its version when a capture group read one, a Check badge when that version is announced, and up to two pieces of evidence; "Found in N places" appears when there were more.

### Response

The final address, the status code, the number of redirects and how much HTML was read, then each redirect with its status. For pasted input it shows only what was pasted.

### Response headers

Every header, with the ones a detection used marked and the technologies they named. Closed by default; Copy result includes it anyway.

## Method

### 1. Fetching the page

For a domain the server requests `https://<domain>/` with `accept: text/html, application/xhtml+xml;q=0.9` and the user agent `TamperboxInspector/1.0 (+https://tamperbox.dev/)`. Redirects are not followed automatically: a 301, 302, 303, 307 or 308 response with a `Location` field ([RFC 9110 section 15.4](https://www.rfc-editor.org/rfc/rfc9110#section-15.4), [section 10.2.2](https://www.rfc-editor.org/rfc/rfc9110#section-10.2.2)) is followed by hand, at most three times, only to HTTPS on the default port, never twice to the same address, and every new host is resolved and checked again. The body is read only when the `Content-Type` ([RFC 9110 section 8.3](https://www.rfc-editor.org/rfc/rfc9110#section-8.3)) is `text/html` or `application/xhtml+xml`, and only up to 262,144 bytes. The whole lookup has a 15 second budget and is rate limited.

Before the response reaches the browser, the server removes `set-cookie` and `set-cookie2` ([RFC 6265 section 4.1](https://www.rfc-editor.org/rfc/rfc6265#section-4.1)), `www-authenticate`, `proxy-authenticate` and `authentication-info`, cuts each header value to 2,048 characters and keeps at most 100 headers. That is why the cookie signature for PHP (`PHPSESSID`) only fires on pasted headers.

### 2. Responses that are not the page

Two statuses mean the HTTPS lookup itself failed: 525 (TLS handshake failed) and 526 (certificate verification failed). They can come from the lookup service or an intermediary, so the detector attributes nothing to the site and reports "Website not inspected" with a single failing finding. Any other status of 400 or more ([RFC 9110 section 15.5](https://www.rfc-editor.org/rfc/rfc9110#section-15.5) and [section 15.6](https://www.rfc-editor.org/rfc/rfc9110#section-15.6)) is read, but the verdict says it is an error page and the finding "HTTP N response" warns that bot checks and error pages often carry the CDN's headers and none of the site's markup. A response that is not HTML is reported as "No HTML inspected", and a body over 256 KiB as "Only the start of the HTML was inspected".

### 3. Signatures

The catalog holds 53 signatures. Each is a set of regular expressions tested against header values or against the raw HTML text, in catalog order. The whole text is searched, including comments, inline scripts and visible text; no DOM is built and no script runs. A match records where it was found and the matched text with about 24 characters of context. A capture group in the matching expression is the version, taken from the first piece of evidence that captures one; the detector remembers which evidence that was.

Some patterns worth knowing: WordPress is read from its generator tag, `/wp-content/` or `/wp-includes/` paths, a `link` header naming `wp-json`, or `x-pingback`. Next.js is read from `__NEXT_DATA__` or `/_next/static/`, and because `__NEXT_DATA__` is also a React signature, Next.js sites list React too. Angular comes from `ng-version`, Vue.js from hashed `data-v-` attributes, SvelteKit from `data-sveltekit-` attributes. Web servers, languages, server frameworks and HSTS come from headers only. Two more rules read real `script src` URLs: `pagead2.googlesyndication.com/pagead/js/adsbygoogle.js` is Google AdSense and `fundingchoicesmessages.google.com/i/` is Google Funding Choices; a lookalike host or a quoted example does not count.

### 4. Announced versions

A version read for a technology in the content system, language, web server or framework categories is a warning: "WordPress 6.4.2 is announced". The rule follows [RFC 9110 section 10.2.4](https://www.rfc-editor.org/rfc/rfc9110#section-10.2.4) on the Server field: "An origin server SHOULD NOT generate a Server header field containing needlessly fine-grained detail and SHOULD limit the addition of subproducts by third parties." The same section explains why: detailed values "potentially reveal internal implementation details that might make it (slightly) easier for attackers to find and exploit known security holes". The detector applies the same reasoning to `X-Powered-By`, `X-Generator`, `X-AspNet-Version` and the HTML `generator` meta name, which the [HTML Standard](https://html.spec.whatwg.org/multipage/semantics.html#meta-generator) defines as identifying the software that generated the document. The advice names the place the version was read: the header by name, the generator tag, or version query strings. Versions of JavaScript libraries, UI frameworks and static site generators are shown without a warning; they are in every visitor's browser anyway.

### 5. Header hygiene

"X-Powered-By is sent" (info) appears when that header exists and no version warning already covers it: the header is not defined by any HTTP specification and helps no visitor. "No HSTS header" (info) appears when headers were inspected and none was `strict-transport-security` ([RFC 6797 section 6.1](https://www.rfc-editor.org/rfc/rfc6797#section-6.1)). Neither is a vulnerability; the [Security Headers Grader](https://tamperbox.dev/security-headers) reviews headers properly.

### 6. The verdict

Lead groups, in order: CMS, Ecommerce, Website builder, Static site generator, JavaScript framework. The first match leads, the next two are companions, and the first CDN signature is named as "behind". The verdict is a pass when no version is announced and a check when one is.

## Standards and conformance

| Specification | What the tool uses | How | Where it stops |
| --- | --- | --- | --- |
| [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), HTTP Semantics | Status codes ([15](https://www.rfc-editor.org/rfc/rfc9110#section-15)), redirection and `Location` ([15.4](https://www.rfc-editor.org/rfc/rfc9110#section-15.4), [10.2.2](https://www.rfc-editor.org/rfc/rfc9110#section-10.2.2)), `Content-Type` ([8.3](https://www.rfc-editor.org/rfc/rfc9110#section-8.3)), `Server` ([10.2.4](https://www.rfc-editor.org/rfc/rfc9110#section-10.2.4)) | Redirects followed by the server, HTTPS only, at most three; body read only for HTML media types; Server and similar fields judged against 10.2.4 | Stricter than a browser: no HTTP, no custom ports, no cookies, no fourth redirect. 525 and 526 are not RFC 9110 codes; they are treated as lookup failures |
| [RFC 6797](https://www.rfc-editor.org/rfc/rfc6797), HSTS | Presence of the `Strict-Transport-Security` field ([6.1](https://www.rfc-editor.org/rfc/rfc6797#section-6.1)) | Reported as info when absent | The directives are not parsed or graded here |
| [RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), Cookies | `Set-Cookie` ([4.1](https://www.rfc-editor.org/rfc/rfc6265#section-4.1)) | Removed from live responses; read only in pasted headers | Cookie attributes are not assessed |
| [HTML Standard](https://html.spec.whatwg.org/multipage/semantics.html#meta-generator), `generator` | The generator meta name | Matched as text, with the version captured | The document is not parsed; a quoted tag can match |

`X-Powered-By`, `X-Generator`, `X-AspNet-Version` and the vendor headers used as signatures are conventions, not standards; the tool treats them as evidence, never as requirements.

## Finding reference

| Finding | Severity | What it means for whoever runs the site | Fix |
| --- | --- | --- | --- |
| HTTPS certificate verification failed (HTTP 526) | FAIL | The lookup could not verify the certificate; nothing about the stack was read | Check the certificate the host serves, then check again |
| HTTPS handshake failed (HTTP 525) | FAIL | The TLS handshake failed; nothing was read | Check TLS on the host |
| X N is announced | CHECK | The exact version of a content system, language, web server or framework is public, a shortcut for anyone matching known vulnerabilities ([RFC 9110 section 10.2.4](https://www.rfc-editor.org/rfc/rfc9110#section-10.2.4)) | Remove the version from the named header or the generator tag; keep the software patched |
| HTTP N response | CHECK | The page read was an error or challenge page; detections may describe that page | Open the site in a browser; paste its real source |
| X-Powered-By is sent | INFO | The header names the stack and helps no visitor | Turn it off in the language or framework |
| No HSTS header | INFO | Browsers may try HTTP first on a later visit ([RFC 6797 section 6.1](https://www.rfc-editor.org/rfc/rfc6797#section-6.1)) | Send Strict-Transport-Security once HTTPS works everywhere |
| Nothing recognised | INFO | No signature matched; not evidence that a technology is absent | None needed; paste the rendered DOM to dig further |
| Only the start of the HTML was inspected | INFO | The body exceeded 256 KiB; late tags can be missed | Paste the part of the page you care about |
| No HTML inspected | INFO | The response was not HTML; only headers were read | Check the address serves a page |

## Guide

### Stop announcing versions

1. Find where each version comes from: the evidence under the technology names the header or the HTML line.
2. Remove it at the source. For nginx, `server_tokens off;`. For Apache, `ServerTokens Prod` and `ServerSignature Off`. For PHP, `expose_php = Off` in php.ini. For ASP.NET, remove `X-AspNet-Version` with `<httpRuntime enableVersionHeader="false" />` and strip `X-Powered-By` in the server configuration. For WordPress, remove the generator tag with `remove_action('wp_head', 'wp_generator');` in the theme.
3. Update the software. The version was public until now.
4. Confirm independently: `curl -sI https://example.com/ | grep -iE '^(server|x-powered-by|x-generator)'` and `curl -s https://example.com/ | grep -io '<meta name="generator"[^>]*>'`. Then check the domain here again; the finding is gone and the technology is still listed, without its number.

Heal it does the same to the source on the page: "Remove the announced versions" drops `X-Powered-By`, strips the number from other headers and from the generator tag, and checks the result here. Nothing is published.

### The page is an error or a bot check

1. Open the site in a browser. If it loads, a bot check, rate limit or geographic rule answered the server.
2. Copy the source from the browser and paste it here; it is read locally.
3. If the site is down for everyone, start with the status code: [RFC 9110 section 15.6](https://www.rfc-editor.org/rfc/rfc9110#section-15.6) for 5xx responses, and the [Website Down Checker](https://tamperbox.dev/website-down-checker) for reachability.

### HTTPS failed

A 525 or 526 means the lookup could not complete or verify TLS. Check the certificate with the [SSL Certificate Checker](https://tamperbox.dev/ssl-checker) or `openssl s_client -connect example.com:443 -servername example.com`, fix the chain or the names it covers, and check again.

### Nothing recognised

Modern single-page applications ship bundles with generic names and render in the browser. Open developer tools, copy the rendered `html` element (Copy outerHTML) and paste it: the scripts' output is then part of the text. Absence of a signature remains absence of evidence.

### Add HSTS

Once every subdomain answers over HTTPS, send `Strict-Transport-Security: max-age=31536000; includeSubDomains` on HTTPS responses only ([RFC 6797 section 7.2](https://www.rfc-editor.org/rfc/rfc6797#section-7.2)). Confirm with `curl -sI https://example.com/ | grep -i strict-transport`.

### Break it cases

| Case | What it loads | What it shows |
| --- | --- | --- |
| Announced versions | Your headers and HTML with `server: Apache/2.4.49 (Unix)` and `x-powered-by: PHP/7.4.3` | Version warnings and the Heal it repair |
| Headers only | Your headers without the HTML | How much the headers alone give away |
| Error page | Your headers on a 503 challenge page | The error-page verdict and warning |
| Next.js app, Shopify store | Fixed sources | Framework and shop signatures |
| Nothing to detect | A plain page | "Nothing recognised" |
| Not a page | A JSON body | "Not a web page" |

The first three are built from what you entered or what the lookup returned; the rest are fixed examples.

## Worked example

The page opens on `www.harbor-supply.example`, a fixture on the reserved `.example` zone answered in the browser, so it costs nothing and never changes. The sample headers carry `server: cloudflare`, `cf-ray`, `x-powered-by: PHP/8.1.27` and a `link` header to `wp-json`; the HTML carries `<meta name="generator" content="WordPress 6.4.2">`, WooCommerce assets, jQuery, Bootstrap, Google Tag Manager, Google Analytics, Cloudflare Web Analytics, Hotjar, Stripe and OneTrust.

**WordPress 6.4.2 with WooCommerce, behind Cloudflare.** Twelve technologies; two versions announced. "WordPress 6.4.2 is announced" tells you to remove the generator tag, because that is where the number was read, even though the `link` header found WordPress first. "PHP 8.1.27 is announced" names the `x-powered-by` header. "No HSTS header" is informational. Heal it offers to remove both versions and to add HSTS; Take it further hands `www.harbor-supply.example` to the headers and certificate checkers, which answer their own samples. Replace the sample with your own domain and every section, card and link is rewritten for it.

## For agents

The Tamperbox MCP server has a `website-technology` operation. Search the catalog, read its input schema and call it with the domain. It uses the same fetch limits (HTTPS, three redirects, 256 KiB) but its own server-side signature catalog, so names and counts can differ from the page; it returns warnings for non-HTML, error statuses and truncation. Keep these with any conclusion:

- Detection reads response headers and initial HTML only; scripts are not run and assets are not fetched.
- A signature can be spoofed, hidden or matched by quoted text; absence proves nothing.
- An announced version is a disclosure, not a confirmed vulnerability.

See [Connect an MCP client](/mcp/connect/) for setup and [Security and privacy](/reference/security/) for where the domain travels.

## Limits

- One HTTPS GET from one place at one moment; geographic rules and bot checks can change what is served.
- At most three redirects and 256 KiB of HTML; cookies and authentication headers are removed.
- Pasted source is searched as text; no DOM is built.
- The catalog covers 53 signatures plus two script-host rules; anything else is not named.
- Nothing is stored.
