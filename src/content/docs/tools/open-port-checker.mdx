The tool page is [tamperbox.dev/open-port-checker](https://tamperbox.dev/open-port-checker). It opens ready to check port 25565, the Minecraft Java default and the port people most often forward at home, and tests it only when you press Check port. This page is the long version: which address is tested and why only that one, how the single connection is classified, what each outcome means for a port forward, and how to confirm a fix.

<div class="tb-callout"><strong>Where processing happens:</strong> choosing a port, the common-port chips and Break it are handled in your browser and send nothing. Opening the page asks the Tamperbox server for your public address. Pressing Check port asks the server to open one TCP connection to that address on that port; it sends nothing over the connection and stores nothing. The address is never taken from anything you type, so the tool cannot be pointed at someone else.</div>

## What the tool answers

1. **Can the internet reach this port on my connection?** Open, refused, or no answer.
2. **What does that mean for my setup?** The service, the address it listens on, the router forward, a firewall, carrier-grade NAT or a VPN.
3. **Is there a catch for this port?** A UDP-only service the TCP test cannot see, or a port home providers often block.

## Inputs

### A port

A number from 1 to 65535, typed or chosen from the common ports: 22 (SSH), 80 (HTTP), 443 (HTTPS), 3389 (Remote Desktop), 25565 (Minecraft), 32400 (Plex), 8096 (Jellyfin) and 8080 (an alternative web port). Anything else is refused in the page with "Not a port". The check runs only on Enter or the Check port button; changing the port says what will be tested and waits.

### Your address

Not an input. The server takes the address the request came from: the `CF-Connecting-IP` value, or the IPv6 address when the edge replaced it with a pseudo IPv4 address. The page shows it under "To your public address" once it has been read. If that address is not public, the check is refused.

## Reading the result

### Verdict and chips

"Ready to check port N on your public IP" until you press Check port, then one of "Port N is open on …", "Port N is closed on …" or "No answer on port N on …". The chip names the outcome and scrolls to the steps.

### Findings

The outcome as a finding, then any caveat for the port, worst first. See the [Finding reference](#finding-reference).

### Take it further

Your address into ASN Lookup (the network it belongs to), and for an open port, `address:port` into TCP Ping to measure it from three regions, and, for port 25565, your address into the Minecraft Server Status Checker. Nothing is put in the URL.

### History

Break it loads a port that shows a caveat before any probe is spent; History logs the change, Revert puts the previous port back, and Heal it offers "Restore input before this break". Typing a new port starts a new History.

### The probe line

From our server in Eastern North America to your public address on the port: "Not checked yet", "Connecting…", then "Open" with the connect time, "Refused" or "No answer".

### What to do next

Numbered steps written for the outcome and the port, with a note when the port is UDP-only or often blocked.

### Checked on this visit

The last twelve checks, newest first, with their outcome and time. Kept in the page only; reloading clears it.

## Method

### 1. The address

The address comes from the request, never from the page. That is why the tool cannot scan other machines, and why a VPN or proxy changes what is tested: the server sees the exit of the tunnel, not your router. With carrier-grade NAT ([RFC 6598, section 4](https://www.rfc-editor.org/rfc/rfc6598#section-4)), the address belongs to your provider's gateway, which is shared by many customers and forwards nothing to you; a port forward on your router cannot work there.

### 2. One connection

The server asks the measurement service in Eastern North America to make one TCP connection to the address and port, limited to 1.5 seconds. A completed three-way handshake ([RFC 9293, section 3.5](https://www.rfc-editor.org/rfc/rfc9293#section-3.5)) is closed at once; nothing is sent.

| Outcome | What came back | Wording |
| --- | --- | --- |
| Open | The handshake completed | "Port N is open", with the connect time |
| Closed | A reset (`ECONNREFUSED`) | "Port N is closed": something answered and said no |
| No answer | Nothing within 1.5 seconds, or an unreachable error | "No answer on port N": inconclusive |
| Unavailable | The measurement did not complete | "The check is unavailable" |

A reset means a device answered for the port but nothing accepted the connection: [RFC 9293, section 3.5.2](https://www.rfc-editor.org/rfc/rfc9293#section-3.5.2) says "A SYN segment that does not match an existing connection is rejected by this means". Silence means the SYN or its answer was dropped, which a missing forward, a firewall and carrier-grade NAT all cause.

### 3. Port caveats

| Port | Caveat | Why |
| --- | --- | --- |
| 51820, 1194, 19132, 3478, 500 | UDP service | WireGuard, OpenVPN's default mode, Minecraft Bedrock, STUN and IPsec use UDP; a TCP result says nothing about them |
| 25, 135, 137, 139, 445 | Often blocked by providers | Inbound mail and Windows file-sharing ports are commonly filtered on home connections |

### 4. Steps per outcome

The steps under What to do next and in the How to fix it card follow the outcome: for open, confirm you meant it and keep the service updated; for refused, start the service, listen on the network rather than localhost, and point the forward at the right device; for no answer, add the forward, allow the port in the device's firewall, compare the router's WAN address for carrier-grade NAT, and turn off any VPN.

## Finding reference

| Finding | Severity | What it means for the device behind the port | Fix |
| --- | --- | --- | --- |
| Port N accepts connections from the internet | PASS | Anyone can reach the service, including scanners | Keep it updated; close the forward when not needed |
| Port N refused the connection | FAIL | The forward or device answers, but nothing listens | Start the service; bind to the network; fix the forward target |
| No answer on port N | CHECK | Dropped before anything answered: no forward, a firewall, CGNAT or a VPN | Add the forward; allow it in the firewall; check for CGNAT |
| … uses UDP | CHECK | The TCP result says nothing about this UDP service | Test the UDP service from outside with the app itself |
| Port N is often blocked by home providers | INFO | The provider may filter it before your router | Ask the provider or use another port |
| This tests the address our server sees | INFO | A VPN, proxy or CGNAT gateway is tested instead of your router | Turn the VPN off; ask for a public address |

## Guide

### A game or media server friends cannot reach

1. On the device, confirm the service listens on the network:

   ```sh
   ss -ltn | grep ':25565'
   ```

   On Windows, `netstat -an | findstr 25565`. A line with `127.0.0.1` means it listens only locally.
2. In the router, forward TCP to the device's LAN address, and reserve that address so it does not change after a restart.
3. Allow the port in the device's firewall.
4. Press Check port. Open means friends can connect; refused or no answer tell you which step to revisit.

### The chain a connection has to cross

A connection from the internet to a game or media server at home passes five places, and each outcome points at one of them:

| Hop | What has to be right | What fails there looks like |
| --- | --- | --- |
| Your provider | It gives your router a public address and does not filter the port | No answer: carrier-grade NAT or an inbound block |
| The router | A forward (or UPnP mapping) for the port and protocol, to the device's current LAN address | No answer: no forward. Refused: a forward to a device where nothing listens |
| The device's firewall | An inbound rule allowing the port | No answer: the firewall drops it silently |
| The service | Running, and listening on the network address or `0.0.0.0` | Refused: nothing listening, or listening only on `127.0.0.1` |
| The application | Accepts the client after the connection | Open here, but the app still rejects players (whitelist, version, password) |

Work from the service outwards: first confirm it listens on the device, then the firewall, then the router, then the provider. Each step is checked again with this tool, so you know which hop the problem was in.

### No answer even with a forward

Open the router's status page and compare its WAN address with the address shown here. If they differ, or the WAN address is between 100.64.0.0 and 100.127.255.255, your provider uses carrier-grade NAT: ask for a public address, or use a tunnel service. If a VPN is on, turn it off and check again.

### Confirm from outside without Tamperbox

From a machine on another network (a phone hotspot works):

```sh
nc -vz -w 2 <your public address> 25565
```

### Break it cases

| Case | What it loads | What it shows |
| --- | --- | --- |
| A UDP-only port | `51820` | The WireGuard note: TCP says nothing about it |
| Often blocked by providers | `25` | The provider-blocking note |
| Port out of range | `70000` | "Not a port"; nothing can be checked |

## Worked example

The page opens ready to check port 25565 on the address it read for you; nothing has been tested yet, so there is no result to read and the result cards wait. Press Check port and the server connects once. On a typical home connection with no forward, the answer is "No answer on port 25565": the router has no rule for the port and drops the connection. The steps say to add a forward for TCP 25565 to the computer running the server and allow it in its firewall. After that, the same check reads "Port 25565 is open" with a connect time, Take it further offers the Minecraft Server Status Checker for your address, and the server list entry there shows what your friends will see.

## For agents

The Tamperbox MCP server exposes the same check as `open_port_checker`, but it tests the public address of whoever makes the request: called from an agent's server, it tests that server, not the user's connection. Use it only to test the machine the agent runs on, and keep these warnings:

- No answer is inconclusive.
- A VPN, proxy or CGNAT gateway is tested in place of the router behind it.
- TCP only.

See [Connect an MCP client](/mcp/connect/) and [Code mode](/mcp/code-mode/), and [Security and privacy](/reference/security/). [TCP Ping](/tools/tcp-ping/) tests any public server from three regions.

## Limits

- Your own public address only; no other address can be entered.
- One TCP connection from one region, limited to 1.5 seconds.
- UDP cannot be tested.
- The history of checks is kept in the page only.
- Nothing you enter is stored.
